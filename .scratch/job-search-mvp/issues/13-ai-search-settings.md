## Что должно заработать

Пользователь на экране настроек выбирает модель OpenAI и поисковый провайдер
`auto`/`Tavily`/`Brave`, а также задаёт общий суточный бюджет. Brave реализуется через
официальный LLM Context API как второй SearchProvider. В режиме `auto` исчерпание
квоты или отсутствие ключа одного провайдера переключает исследование на другой без
выдумывания результатов.

## Из брифа, дословно

> «Суточный бюджет пусть будет отдельной настройкой в разделе настроек.»
>
> «Модель выбери сам, но оставь возможность изменить модель в настройках.»
>
> «Tavily подтверждаю, однако добавь также возможность использовать Brave search.»

## Критерии приёмки

- [ ] Настройки содержат суточный бюджет, модель и `auto`/`Tavily`/`Brave`; значения сохраняются в профиле и валидируются.
- [ ] Начальная модель — `gpt-5.6-luna`; вызовы используют модель профиля, а не только process env.
- [ ] Brave использует `BRAVE_SEARCH_API_KEY` только из окружения и официальный `/res/v1/llm/context`.
- [ ] Ответ Brave служит только выбору URL; проверенные факты по-прежнему требуют безопасного чтения actual page.
- [ ] `auto` переключается только по явной unavailable/quota причине и сохраняет прозрачный progress/provider provenance.
- [ ] Стоимость поиска резервируется/учитывается общим budget ledger; неизвестная цена запрещает платный вызов.
- [ ] Нет ключей, CV или иных личных данных в запросах, логах, исключениях и HTML.
- [ ] Fixture HTTP/UI tests покрывают success, invalid response, quota, fallback и сохранение настроек; live сеть не обязательна.
