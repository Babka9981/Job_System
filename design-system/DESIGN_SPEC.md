# Спецификация дизайна

## 1. Направление

Современный административный интерфейс для продолжительной работы операторов:

- визуальный ориентир — Vuexy Vertical Menu Dashboard;
- собственный дизайн без прямого копирования;
- фиолетовый акцент;
- светлая и тёмная темы;
- карточная композиция;
- умеренно компактная плотность;
- desktop-first от 1280 px;
- полноценный планшетный и рабочий мобильный режим;
- WCAG 2.2 AA.

Интерфейс должен оставаться информационно насыщенным, но не выглядеть тесным.
Декоративные элементы не должны конкурировать с рабочими данными.

## 2. Технологические принципы

Спецификация не зависит от фреймворка. Эталонная реализация использует React,
TypeScript и собственный CSS без обязательного UI-kit.

- Все цвета задаются семантическими переменными из `tokens.css`.
- Компоненты не содержат случайных локальных цветов.
- Иконки — единообразные контурные SVG с `stroke: currentColor`.
- Состояния и бизнес-смысл передаются текстом, а не одним цветом.
- Новая страница собирается из общих примитивов, а не из уникальной разметки.

## 3. Типографика

Основной шрифт — Inter:

```css
font-family:
  Inter,
  ui-sans-serif,
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  sans-serif;
```

Рекомендуемая шкала:

| Элемент                 |   Размер |     Вес |
| ----------------------- | -------: | ------: |
| Вспомогательная подпись | 12–13 px | 600–700 |
| Основной текст          | 14–16 px | 400–500 |
| Label формы             | 14–16 px | 600–700 |
| Заголовок карточки      | 16–20 px | 700–800 |
| Заголовок страницы      | 24–35 px | 750–850 |
| Крупная метрика         | 24–40 px | 750–850 |

Основной межстрочный интервал — `1.45–1.6`. Длинные технические значения
переносятся через `overflow-wrap: anywhere`; исходный текст и код используют
моноширинный шрифт.

## 4. Оболочка приложения

### Desktop

- Левая панель: `16rem` (около 256 px).
- Верхняя панель: `4.25rem` (около 68 px).
- Sidebar и topbar закреплены при прокрутке.
- Основная область занимает оставшееся пространство.
- Отступ основной области: `clamp(1rem, 3vw, 2rem)`.
- Sidebar можно полностью скрыть кнопкой в topbar.
- Активный раздел имеет фиолетовый фон и контрастный текст.

Topbar содержит слева кнопку меню и название текущего раздела, справа — статус
соединения, переключатель темы, пользователя и действия с сессией.

### Планшет — до 62rem / 992 px

- Постоянный sidebar заменяется выезжающим drawer.
- За drawer появляется затемняющий backdrop.
- Drawer закрывается по `Escape`, клику по backdrop и выбору раздела.
- После закрытия фокус возвращается на кнопку открытия.

### Мобильный режим — до 42rem / 672 px

- Topbar может занимать несколько строк.
- Формы и карточные сетки переходят в одну колонку.
- Основные кнопки занимают доступную ширину.
- Горизонтальная прокрутка разрешена только внутри таблиц или специальных
  контейнеров, но не у всей страницы.

Дополнительный breakpoint `48rem / 768 px` применяется к двухколоночным экранам
входа и вспомогательным композициям. На ширине `80rem / 1280 px` сложные рабочие
сетки могут переходить к более простой компоновке.

## 5. Поверхности и карточки

Базовая карточка:

```css
.ui-card {
  min-width: 0;
  padding: 1.25rem;
  border: 1px solid var(--border-subtle);
  border-radius: var(--radius-card);
  background: var(--surface-raised);
  box-shadow: var(--shadow-sm);
}
```

Правила:

- внутренний отступ обычно 20 px;
- расстояние между карточками 16–24 px;
- карточки в одной строке не обязаны иметь одинаковую высоту;
- вложенные поверхности используют `--surface-canvas`, `--surface-soft` или
  `--surface-sunken`;
- крупные рабочие страницы не ограничиваются узкой маркетинговой колонкой;
- таблицы помещаются в собственный прокручиваемый контейнер.

## 6. Сетка и интервалы

Использовать базовый шаг 4 px. Предпочтительные интервалы:

`4, 8, 12, 16, 20, 24, 32, 48 px`.

Адаптивная сетка полей:

```css
.field-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(14rem, 100%), 1fr));
  gap: 1rem;
}
```

Не размещать textarea и кнопку отправки в тесной строке. Большие редакторы,
подтверждения и основные действия получают отдельный ряд.

## 7. Формы

Порядок элемента формы:

1. label;
2. control;
3. подсказка;
4. локальная ошибка.

```css
.form-control {
  width: 100%;
  min-width: 0;
  min-height: 2.75rem;
  padding: 0.65rem 0.75rem;
  border: 1px solid var(--border-strong);
  border-radius: 0.65rem;
  background: var(--surface-canvas);
  color: var(--text-primary);
  font: inherit;
}
```

- Минимальная интерактивная высота — 44 px.
- Textarea изменяет размер только вертикально.
- Disabled-состояние читаемо, но приглушено.
- Ошибка располагается рядом с полем и связывается через `aria-describedby`.
- Checkbox и radio используют `accent-color: var(--primary)`.

## 8. Кнопки

- Primary: фиолетовый фон, контрастный текст, вес 700–750.
- Secondary: нейтральный фон или прозрачность, выраженная граница.
- Danger: красный текст/мягкий красный фон только для опасных действий.
- Disabled: `cursor: not-allowed`, сниженная непрозрачность.
- Hover не должен менять геометрию элемента.
- Focus всегда заметен:

```css
:where(button, a, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: 3px solid var(--focus-ring);
  outline-offset: 3px;
}
```

## 9. Статусы и обратная связь

Поддерживаются пять тонов: `neutral`, `info`, `success`, `warning`, `danger`.

- Badge — компактный статус с мягким фоном и текстом.
- Banner — сообщение с цветной левой границей.
- Ошибка использует `role="alert"`.
- Фоновый статус использует `role="status"` или `aria-live`.
- Цвет всегда сопровождается текстом или значком.

## 10. Темы

- Первое посещение использует системный `prefers-color-scheme`.
- Переключатель находится в topbar и на экране входа.
- Выбор хранится в `localStorage`.
- Изменение синхронизируется между вкладками через событие `storage`.
- На `<html>` устанавливается `data-theme="light|dark"`.
- Тема применяется до гидратации/первого отображения для исключения вспышки.
- Все элементы, включая поля, scrollbars и системные controls, должны корректно
  работать в обеих темах.

## 11. Иконки

- Контурный стиль, обычно 20×20 px.
- `fill: none`, `stroke: currentColor`.
- `stroke-width: 1.6–1.8`.
- Скруглённые окончания и соединения линий.
- Декоративные SVG получают `aria-hidden="true"`.
- Иконочные кнопки получают понятный `aria-label`.

Можно использовать собственные inline SVG либо Lucide. Не смешивать несколько
визуально разных наборов иконок.

## 12. Базовые компоненты

Перед разработкой страниц создать:

- `AppShell`;
- `Sidebar` и мобильный `Drawer`;
- `Topbar`;
- `PageHeading`;
- `Card` и `MetricCard`;
- `FieldGrid`;
- `Toolbar` и `ActionGroup`;
- `StatusBadge`;
- `FeedbackBanner`;
- `TableContainer`;
- `EmptyState`, `LoadingState`, `ErrorState`;
- `ThemeToggle`;
- `Dialog`;
- `Pagination`.

## 13. Состояния страниц

Каждый загружаемый раздел должен проектироваться сразу для состояний:

- первоначальная загрузка;
- фоновое обновление;
- данные загружены;
- пустой результат;
- ошибка с повторной попыткой;
- отсутствие прав;
- сохранение;
- успешное действие;
- конфликт версии;
- потеря соединения.

Пустое состояние содержит короткий заголовок, объяснение и одно рекомендуемое
действие, если оно возможно.

## 14. Доступность

- Целевой уровень: WCAG 2.2 AA.
- Контраст обычного текста — не менее 4.5:1.
- Полная клавиатурная навигация.
- Видимый `focus-visible`.
- Семантические заголовки и landmarks.
- `label` для каждого поля.
- `aria-current="page"` для активной навигации.
- `aria-expanded` и `aria-controls` для drawer/collapse.
- Skip-link «Перейти к содержимому».
- Закрытие overlay по Escape.
- Сохранение функций при увеличении текста до 200%.
- Минимальная интерактивная область около 44×44 px.

## 15. Запреты

- Не копировать платные материалы Vuexy без лицензии.
- Не смешивать произвольные цвета с семантическими токенами.
- Не передавать состояние только цветом.
- Не скрывать focus outline без равноценной замены.
- Не допускать горизонтальную прокрутку всей страницы.
- Не использовать фиксированную высоту для динамического текста без безопасной
  прокрутки или раскрытия.
- Не менять бизнес-логику ради визуального сходства с референсом.
