# Единый ограниченный deadline для OpenAI-вызова

## Контекст

Production-проверка большого CV выявила два последовательно скрытых ограничения: socket cap worker в 30 секунд обрезал разрешённые transport 45/120 секунд, а после его устранения transport продолжал применять собственный default 45 секунд вместо доступных 120. Альтернативой было независимо настраивать timeout каждого слоя, оставляя более короткому внутреннему лимиту право завершать запрос.

## Решение

Задать единый bounded default OpenAI request timeout до 120 секунд и передавать его как hard deadline в родительский `run_http_exchange`. Socket timeout worker равен оставшемуся времени в пределах этого deadline; явный более короткий caller deadline сохраняет приоритет и никогда не расширяется. Родитель завершает зависший subprocess по hard deadline.

## Почему

Независимые defaults создают неочевидный эффективный минимум: увеличение внешнего timeout не помогает, если transport или socket завершают запрос раньше. Один абсолютный deadline делает поведение слоёв согласованным и измеримым, при этом сохраняет конечную верхнюю границу выполнения и не ослабляет budget accounting.

## Последствия

Worker и transport обязаны вычислять оставшееся время от одного deadline, а не вводить собственные меньшие defaults. Долгий profile extraction получает полный bounded интервал, но после его истечения завершается fail-closed; uncertain попытка остаётся pending, секреты не передаются через argv/environment, а повтор проходит только через budget-enforced gateway.
