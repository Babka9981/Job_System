# Серверный монолит для персонального сервиса

## Контекст

Система предназначена для одного владельца и разворачивается на его VPS. Альтернативами были отдельный SPA с API и несколькими сервисами либо единый серверный проект, который владеет HTML, сессиями, данными и фоновыми командами.

## Решение

Использовать один Django-проект с серверным HTML, session auth и SQLite на постоянном диске; регистрацию закрыть, а владельца создавать локальной CLI-командой.

## Почему

Монолит соответствует единственному владельцу и трём основным экранам, уменьшает число сетевых и эксплуатационных границ и позволяет применять CSRF, авторизацию и миграции в одном месте. SPA/API или набор сервисов добавили бы отдельный контракт аутентификации, сборку клиента и эксплуатацию нескольких процессов без требуемой для пилота выгоды.

## Последствия

UI и доменная логика выпускаются согласованно, а резервное копирование охватывает один основной persistent store. Горизонтальное масштабирование, независимые релизы клиента и высокая конкурентная запись не являются целями этой архитектуры; переход к ним потребует выделения API и миграции с SQLite.
