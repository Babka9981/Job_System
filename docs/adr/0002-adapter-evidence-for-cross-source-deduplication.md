# Дедупликация между источниками только по подтверждённым данным

## Контекст

Одна вакансия может встретиться в нескольких источниках, но одинаковый URL не доказывает тождество: ссылка может вести на карточку, листинг или категорию. Универсальная URL-эвристика рассматривалась и была отклонена после того, как сборка показала, что без знаний адаптера она не различает эти случаи (D01).

## Решение

Внутри источника считать идентичностью `source + external_id`, а при отсутствии ID — `source + точный URL`. Между источниками объединять записи только по совпадающему непустому нормализованному содержимому либо по permalink, который конкретный адаптер подтвердил как идентификатор объявления; сомнительные случаи оставлять раздельными.

## Почему

Ложное объединение необратимо смешивает ссылки и пользовательские состояния разных вакансий и опаснее временного дубля. Только адаптер знает семантику URL своего источника, а content evidence даёт проверяемое основание независимо от формы ссылки.

## Последствия

Модель источников должна хранить внешние ID, точные URL, хеши и тип доказательства, а адаптеры — явно подтверждать permalink. Дублей может остаться больше, зато автоматическое объединение не уничтожает различия; ручной URL требует явного подтверждения владельца или adapter evidence.
