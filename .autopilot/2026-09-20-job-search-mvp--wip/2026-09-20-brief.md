# Персональный поиск работы — краткое ТЗ MVP

Версия 0.3 · 9 сентября 2026 года · Владелец: Илья

Статус: проект ТЗ для разработки. Проверены открытые страницы и документация источников; авторизация в аккаунтах, запуск интеграций и развёртывание на VPS ещё не выполнялись.

Изменения версии 0.3: согласовано добавление Himalayas и Jobicy в первую очередь, CryptoJobsList — после получения API-ключа. Список целевых компаний и их прямой мониторинг перенесены на отдельный следующий этап. Исследование компании при подготовке отклика и профиль из резюме включены в версии 0.2.

**Цель и минимальная реализация**

Личный сервис для одного пользователя на его VPS: собирать новые вакансии, отбирать подходящие, присылать обновления в Telegram, автоматически исследовать компанию в открытом интернете и готовить два вида откликов через LLM. Целевой список мониторинга — 9 сайтов (6 исходных и 3 согласованных дополнительных) и 41 Telegram-источник из приложения к этому документу, всего 50 источников. Исследование компании охватывает публичные источники за пределами этого списка и не требует заранее собранного перечня работодателей.

Рекомендуемая реализация: один проект на Django, серверные HTML-страницы и SQLite на постоянном диске. Планировщик ОС запускает сборщик из того же проекта. Один внешний LLM API с возможностью веб-поиска и чтения страниц, один Telegram-бот для уведомлений. Если выбранный провайдер не поддерживает веб-поиск, подключается один поисковый API с загрузчиком публичных страниц. Docker Compose для запуска, Caddy для HTTPS. Это предложение по реализации, а не проверка текущего VPS.

Для первой версии достаточно трёх экранов: «Вакансии», «Мой профиль», «Источники». Автоматическая отправка откликов, аналитические панели, обучение модели и отдельная векторная база в MVP не требуются.

Поиск по названию — предварительный фильтр. Product Marketing и Product Designer сами по себе не являются продуктовыми менеджерами. Customer Success с продажами и обычная операторская поддержка не равны руководству поддержкой. Смежные названия оцениваются по обязанностям.

Зарплату хранить вместе с валютой, периодом, gross/net и составом: фиксированная часть, бонусы, токены/доли. Годовую сумму можно делить на 12 только для сопоставимого показателя. $60 000 в год соответствует $5 000 в месяц на той же базе, а не автоматически «на руки». Почасовую ставку без объёма часов и совокупную компенсацию без фиксированной части не считать подтверждённым выполнением цели. Для других валют нужен датированный курс; до подключения такого пересчёта сравнение отмечать как неуточнённое.

Вилки без зарплаты сохранять. Вилка, пересекающая цель, остаётся с пометкой о необходимости переговоров. Автоматически исключать по оплате только при известной сопоставимой базе, когда вся вилка ниже порога. До уточнения gross/net жёсткий отсев по зарплате отключён.

Worldwide remote, remote из определённых стран и remote с ограничением по часовому поясу различать. География поиска «весь мир» не подтверждает право кандидата работать в каждой стране. Неизвестные условия найма и релокации отмечать для уточнения.

**Карточка вакансии и простая оценка**

Карточка содержит название, компанию, роль, отрасль, формат, ограничения по географии, зарплату, язык, дату публикации и последней проверки, доступный текст, ссылку на конкретную вакансию/пост и источник. Даты, зарплату и условия, которых нет в источнике, не придумывать. Контакт Telegram показывать только если он действительно указан, сохраняя связь с соответствующим объявлением.

Три результата оценки:

- «Подходит»: соответствует направлению поиска, без известных препятствий.
- «Уточнить»: релевантная роль, но неизвестны или спорны существенные условия.
- «Не подходит»: есть конкретное явное несоответствие.

Дополнительно — 1–3 короткие причины и вопросы работодателю. «Подходит» означает приоритет для просмотра, а не обещание оффера или подтверждение неизвестной зарплаты. Выше показывать удалённые позиции, затем релокацию; внутри — более свежие.

Предварительная фильтрация использует слова и поля источника; она должна быть достаточно широкой, чтобы не терять релевантные объявления. Далее, где обработка разрешена, один LLM-запрос извлекает структуру и объясняет соответствие. Повторно неизменённый текст не обрабатывать. Пробелы в информации не считать отрицательным ответом.

**Согласованный порядок подключения**

1. В первую очередь реализовать Remote OK и Web3.career из исходного списка, а также Himalayas и Jobicy из новых источников. Ожидание ключа одного источника не блокирует запуск остальных.
2. CryptoJobsList подключить после получения API-ключа и подтверждения условий доступа. Остальные исходные сайты и Telegram подключать по предусмотренным выше способам и доступности данных.
3. Для фонового мониторинга новых площадок использовать обычные HTTP-запросы к API. Отдельный универсальный MCP-клиент ради этих трёх источников в MVP не требуется. RVC использует свой предусмотренный MCP-доступ. Возможности MCP Himalayas и Jobicy для дополнительного поиска и исследования компании остаются вариантом последующего расширения.
4. Список целевых компаний собрать отдельно позднее. Прямой мониторинг через Greenhouse, Ashby или Lever реализовывать следующим этапом после выбора работодателей; подготовка этого списка и модулей не входит в текущую поставку. Автоматическое исследование компании при подготовке письма или сообщения остаётся в MVP и работает для компании из выбранной вакансии.

Startup Jobs и Remotive оставить в резерве; их подключение не входит в согласованное расширение текущего списка. При возврате к ним учитывать [14-дневное окно бесплатного доступа Startup Jobs](https://startup.jobs/api) и требование [обновлять или удалять данные в течение семи дней](https://startup.jobs/terms/api), а также [24-часовую задержку бесплатной ленты Remotive](https://github.com/remotive-com/remote-jobs-api).

**Telegram**

Для чтения выбранных источников нужен клиентский API с авторизацией аккаунта, имеющего доступ к ним; бот для уведомлений — отдельный компонент. [Получение истории](https://core.telegram.org/method/messages.getHistory) доступно пользовательским аккаунтам. При внедрении проверить все 41 адрес; в открытой проверке просмотрены только страницы @forproducts, @product_jobs и @workingincrypto.

Для каждой доступной группы/канала получать новые сообщения после сохранённой позиции, с учётом ограничений API. Один пост может содержать несколько вакансий. Для каждой сохранять ссылку на конкретный пост; ссылка на закрытый источник открывается только при наличии доступа. Учитывать редактирование и удаление сообщений в рамках доступных событий/проверок.

[Правила Telegram API](https://core.telegram.org/api/terms) и [условия использования контента](https://telegram.org/tos/content-licensing) ограничивают применение полученных сообщений в AI-системах; исключения связаны с явным согласием соответствующих пользователей на конкретный контекст. Авторизация своего аккаунта не заменяет это согласие.

Практический минимальный вариант для проверки допустимости: чтение и обычные текстовые фильтры в рамках разрешённого использования клиента. LLM-обработку Telegram-текста включать только при подтверждённом основании; иначе использовать независимо полученное разрешённое описание вакансии из первоисточника. Ручная вставка или пересылка сама по себе не меняет условия использования контента. Вакансия только с Telegram-текстом без такого основания может иметь обычную карточку по правилам, но полный LLM-анализ и письмо по этому описанию не заявляются доступными.

**Сопроводительное и сообщение рекрутеру**

В карточке две кнопки: «Сопроводительное письмо» и «Сообщение рекрутеру». Нажатие любой кнопки автоматически запускает исследование компании либо использует его свежий результат. Генерация объединяет проверенный профиль, конкретное доступное описание вакансии и подтверждённые сведения из исследования. Пользователь может дополнить их ссылкой или заметкой.

Настройки: русский/английский, краткость, тон и свободное указание акцента. После генерации — редактирование, сохранение и копирование. Текст рекрутеру короче письма; контакт показывать рядом, если он указан в объявлении. Отправку выполняет пользователь.

Письмо использует 1–2 релевантных факта о компании и подходящие кейсы кандидата. Сообщение рекрутеру использует тот же результат исследования, но выбирает один самый уместный аргумент. В обоих случаях факты связываются с требованиями конкретной роли; общую справку о компании целиком в текст не вставлять.

LLM не выдумывает опыт, достижения, зарплату, имя рекрутера или факты о компании. Если данных недостаточно, предлагает уточнение. Исследование компании не заменяет отсутствующее описание вакансии: требования неизвестной роли не достраиваются по новостям. Письмо по неполному описанию явно помечается как подготовленное по ограниченной информации.

**Автоматическое исследование компании**

Это целевой поиск по открытому интернету с чтением найденных страниц. Он выполняется при подготовке отклика на выбранную вакансию и не ждёт очередного планового обхода источников. Отдельный экран не нужен: ход поиска и результат отображаются в карточке.

1. Определить компанию и её официальный домен по вакансии, ссылке работодателя и найденным подтверждениям. Не смешивать одноимённые компании или рекрутинговое агентство с нанимающей компанией. Если идентификация неоднозначна, запросить домен; до уточнения использовать только сведения из вакансии.
2. Изучить подходящие страницы сайта: продукт, решения, «О компании», карьерный раздел, блог/новости, документацию. Выбирать страницы по роли: продукт и стратегия для продакта, процессы и интеграции для проджекта, клиентский опыт и поддержка для руководителя поддержки.
3. Найти релевантные внешние публикации: новости, интервью руководителей, запуски продуктов, партнёрства, выход на рынки и публичные профессиональные страницы компании. Для новостей по умолчанию приоритет последним 12 месяцам; более старые сведения использовать, если они значимы и остаются актуальными. Приоритет фактам из первоисточников и надёжных публикаций.
4. Составить краткую справку: продукт, клиенты и рынки, актуальные события, требования роли и 2–3 соответствующих кейса из профиля. Для каждого факта о компании сохранить URL, дату публикации/события, когда они известны, и время проверки. Для каждого кейса кандидата — ссылку на запись профиля или страницу резюме. Гипотезы о потребностях компании отделять от заявленных требований.
5. Сгенерировать выбранный текст. В раскрываемом блоке «О компании» показать 3–5 полезных фактов, основания персонализации и ссылки. По умолчанию технические ссылки на источники остаются в этом блоке и не включаются в копируемый текст письма или сообщения.

Поисковый сниппет служит для выбора страницы; важные утверждения проверяются по её содержимому. Неоднозначные или противоречивые сведения помечаются и не попадают в отклик как установленные факты. Отзывы и неподтверждённые негативные сообщения не используются для персонализации первого обращения. Не заявлять исчерпывающий охват интернета.

Начальные ограничения одного исследования: до 5 поисковых запросов, до 8 содержательных страниц и 90 секунд; это редактируемые лимиты, а не обещание времени ответа. Поиск должен действительно выходить в интернет: знания модели без веб-источников не считаются выполненным исследованием. Запросы включают компанию, продукт и роль; резюме, контакты и другие личные данные кандидата в поисковый запрос не передаются.

Результат исследования компании кэшировать на 24 часа, если условия источников допускают этот срок. Письмо и сообщение используют общую справку, а подбор кейсов обновляется для конкретной вакансии и текущей версии профиля. Кнопка «Обновить исследование» запускает новый поиск. Изменение компании/домена сбрасывает кэш; при смене вакансии проверить, хватает ли справки для новой роли.

Если сайт недоступен, продолжить по другим доступным источникам. При исчерпании времени/бюджета или отсутствии достоверных результатов предложить черновик по резюме и вакансии с отметкой «Исследование частичное» либо «Исследование недоступно». Не подменять сбой вымышленными новостями. Соблюдать ограничения доступа и хранения источников; веб-поиск не отменяет ограничений Telegram и сайтов вакансий. В лимите расходов учитывать как LLM, так и поиск/чтение страниц.

**Мониторинг и сохранение**

Предлагаемое расписание: 09:00, 13:00, 17:00 и 21:00 в выбранном пользователем часовом поясе. Расписание редактируется; часовой пояс задаётся перед включением. Стартовая загрузка — до 7 последних дней, если источник предоставляет такую историю. Далее — новые и изменившиеся записи. Более узкое доступное окно источника показывать явно.

Для Himalayas JSON API достаточно одной загрузки в сутки с учётом ежедневного обновления данных. Jobicy и CryptoJobsList проверять в каждом из четырёх циклов, соблюдая лимиты доступа. Период проверки сервиса и частоту обновления данных поставщиком показывать раздельно. Сохранять фактическую дату публикации и время первого обнаружения; повторное получение старой записи не делает её новой. Если выдача упирается в лимит и пагинации нет, показывать статус «Ограниченная выдача».

После цикла — одна подборка новых подходящих вакансий и требующих уточнения, с короткими причинами и ссылками. При большом количестве — первые 10 и ссылка на полный список. Повторно ту же вакансию не уведомлять; ошибка источника не считается отсутствием вакансий.

Дубли определять по ID источника и исходному URL; между источниками — по ссылке работодателя либо совпадающему тексту. Совпадение компании и названия само по себе недостаточно: могут различаться страна и команда. При уверенном объединении сохранять все доступные ссылки и пользовательский статус с учётом правил хранения.

Минимальные статусы пользователя: «Новая», «Сохранена», «Откликнулся», «Интервью», «Закрыта». Для закрытия — краткая заметка: неинтересно, отказ, оффер и т. п. Отдельно хранить актуальность объявления: неизвестна/активна/снята. Отсутствие в ограниченной API-выдаче не означает снятие.

Один процесс сбора за раз; сохранять прогресс после успешной обработки страниц/сообщений. После сбоя продолжать со своей позиции. Лимиты и временные ошибки обрабатывать без бесконечных повторов. На ошибки авторизации показывать действие «переподключить». Лимит LLM-расходов задаётся настройкой; необработанные записи при его достижении остаются ожидающими, а не исчезают.

**Развёртывание и приёмка**

Личный вход, закрытая регистрация, HTTPS. Файлы резюме, API-ключи и Telegram-сессия недоступны публично и не попадают в логи. В LLM передавать только нужные данные профиля и разрешённые тексты вакансии и источников исследования; внешние тексты не должны управлять доступом к аккаунтам или отправкой сообщений. Загрузчик веб-страниц обращается только к публичным HTTP(S)-адресам, без доступа к внутренней сети VPS и без передачи учётных данных сайтов вакансий сторонним доменам.

Резервировать базу и резюме согласованным способом; временные данные с ограниченным сроком хранения не включать в постоянные копии. Перед запуском проверить ресурсы VPS, существующие сервисы, домен и доступ к API из его сети.

Критерии готовности первой рабочей поставки:

1. Профиль загружается и редактируется; три направления и все 50 источников (9 сайтов и 41 Telegram-источник) заведены. Резервные площадки и будущий список компаний в это число не входят.
2. Каждый источник имеет честный статус: работает, ограниченная выдача, нужны данные доступа, либо подключение не готово с конкретной причиной.
3. Для подключённых источников свежая тестовая вакансия появляется после цикла с точной ссылкой; повторный цикл не создаёт дубль.
4. Вакансия без зарплаты сохраняется; ограничение страны у remote видно; несовпадающие роли не проходят лишь из-за похожего слова.
5. Каждая из двух кнопок запускает исследование или использует его свежий кэш. Для вакансии с достаточным разрешённым описанием создаются оба вида текста на фактах профиля и компании; результат можно исправить и скопировать.
6. Уведомление приходит владельцу; сбой отдельного источника виден и не останавливает остальные.
7. После перезапуска сохраняются профиль, пользовательские статусы и позиция сбора; ограниченные по сроку данные удаляются вовремя.
8. В карточке видны прочитанные веб-источники и время исследования; факты в персонализированном тексте прослеживаются до источника о компании и записи профиля. Одноимённые компании не смешиваются, а повторная генерация второго вида текста использует общую справку.
9. При недоступном поиске/сайте, конфликтующих сведениях и истечении лимита сервис честно сообщает об ограничении и позволяет подготовить текст по имеющимся проверенным данным.
10. Himalayas и Jobicy проходят проверку получения и повторной обработки реальных объявлений через API. При отсутствии ключа CryptoJobsList показано, что требуется для подключения; остальные источники работают. После добавления ключа проверяются пагинация, исходная ссылка и отсутствие повторных уведомлений.

Первую поставку с частью источников называть пилотом. Полное покрытие согласованного списка из 50 источников считать достигнутым только после проверки всех подключений; невозможный способ доступа заменить согласованным рабочим вариантом, а не скрывать источник из перечня. Список целевых компаний и их прямой мониторинг не являются условием готовности пилота.

**Что уточнить перед настройкой**

- $5 000 — в месяц? Это gross, net или сумма по B2B-контракту до личных налогов?
- Страна/часовой пояс предполагаемой работы и существенные ограничения найма. Резюме получено; английский C1 указан в нём. Уточнить текущую роль и даты работы в GoDefi.
- Домен и параметры VPS; доступный API-план Remote Rocketship, токен Web3.career, выбранный провайдер LLM с веб-поиском либо отдельный поисковый API и бюджет вызовов.
- API-ключ CryptoJobsList и выданные вместе с ним условия и лимиты. Himalayas и Jobicy для описанного публичного поиска ключей не требуют. Получение ключа CryptoJobsList не задерживает первую поставку.
- Способы разрешённого доступа к Telegram, Remocate и ITCharm. Секреты вводятся в настройках развёрнутого сервиса или на VPS.
